# 🔴 Install — judging fix, before fair day

**Date:** 2026-09-06 · **Time:** ~5 minutes · **Risk:** low (no data is written until you run the builds)

The dry run found two ways the judging chain **silently loses entries**. The fix is
tested but Claude cannot write to Apps Script, so it needs your hands.

## Why it matters

**Alice Leger (HF2026-1018) is currently invisible to the judging sheets.** She entered
three gymkhana events — barrel race, musical pads, pole bending. The script reads only the
`Show Sections` column; hers are all in `Gymkhana Sections`. She produces one entry reading
"(no section recorded)" and the build reports *"No problems."* On fair day she shows up for
barrel racing and is on no sheet.

## Steps

1. Open the Apps Script project **"Havelock Forms"** (on `straydogmedia.ca@gmail.com` — the
   one bound to the Master Workbook, where the 🏆 menu comes from).
2. Open the `HF_JudgingSystem` file.
3. Select all, and paste in the full contents of **`HF_JudgingSystem.gs` from this folder**.
   Save.

   > ⚠️ This is `HF_JudgingSystem.gs`. Do **not** touch `Code.gs` — and never paste the
   > `Code.gs` in this folder anywhere, it is the stale pre-migration copy.

4. Run, in order, from the function dropdown or the 🏆 menu:

   | Function | Expect |
   |---|---|
   | `HF_buildEntries` | `ENTRIES rebuilt: ~38 judgeable entries from 20 registration rows. ⚠ 1 row(s) need attention` |
   | `HF_makeJudgingSheets` | `JUDGING SHEETS built: N section(s)…` |
   | `HF_verify` | `✅ ALL CHECKS PASSED` |

5. Open **ENTRIES** and confirm **HF2026-1018 now has three rows** (barrel race, musical pads,
   pole bending) — not one saying "(no section recorded)".

The one flagged row should be **HF2026-1019**: an abandoned Equestrian submission with no
name, no contact and no events. That flag is correct — it is a real empty registration.

## ⚠️ Timing

`HF_buildEntries` **refuses to renumber once placings have been recorded**, by design. Run it
**before** judging starts. If new registrations arrive between now and fair day, rebuild
again — but not after any placing is written.

## What changed in the script

| Fix | What |
|---|---|
| A | New `hfJoinSections_()` — Equestrian now reads **both** `Show Sections` and `Gymkhana Sections` |
| B | A position-only registration with no events is **flagged**, not given a phantom entry |
| C | `HF_verify` counts only `E####` as ENTRY #s — the ⚠ NEEDS ATTENTION block was inflating the count and could have failed the uniqueness gate on cheque writing |

Tested end to end against all 20 live registration rows: 38 entries, 1 flag, verify passes,
money chain reconciles to the penny. 35 checks green in `judging-tests/gas-test.js`.
